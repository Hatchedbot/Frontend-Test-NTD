Anatomía de la API de Tareas

Cada clic en la interfaz dispara un viaje de ida y vuelta entre tres piezas independientes: el navegador, la API Flask y la base de datos SQLite. Así es como luce ese viaje, paso a paso.

02 · Los verbos REST

Cinco rutas, cinco operaciones SQL

Cada verbo HTTP tiene un propósito fijo. La API expone las cinco combinaciones posibles sobre el recurso /tareas.

MétodoEndpointFunción en el frontendOperación SQLRespuesta
GET /tareas cargarTareas() SELECT * FROM tareas ORDER BY id 200 OK
GET /tareas/<id> — (no usada desde la UI) SELECT * FROM tareas WHERE id = ? 200 / 404
POST /tareas crearTarea() INSERT INTO tareas (tarea, estado) 201 / 400
PUT /tareas/<id> actualizarTarea() UPDATE tareas SET tarea=?, estado=? 200 / 404 / 400
DELETE /tareas/<id> eliminarTarea() DELETE FROM tareas WHERE id = ? 200 / 404

04 · De una API a varios microservicios

El mismo patrón, multiplicado

Un microservicio no es más que esto: una API con su propia base de datos, dueña exclusiva de sus tablas. Encadena varios y tienes una arquitectura de microservicios.

Construido con Flask + SQLite en el backend y HTML/CSS/JS puro en el frontend, sin frameworks, para que cada capa del patrón cliente-servidor quede a la vista.
